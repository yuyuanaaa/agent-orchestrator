## 修复：接口文档 500（springdoc/knife4j 版本冲突，最终弃用 knife4j）
- 现象（两阶段）：
  1. 访问 `/v3/api-docs/default` 报 `NoSuchMethodError: ControllerAdviceBean.<init>(Object)`；
  2. 换成 knife4j 4.5.0 + springdoc 2.8.13 后，又报 `NoSuchMethodError: SpringDocConfigProperties.getGroupConfigs()`。
- 根因（两阶段是同一问题的两面，无法同时满足）：
  - Spring Framework 6.2 移除了 `ControllerAdviceBean(Object)` 构造器 → 需要 springdoc ≥ 2.7.x；
  - 但 springdoc 2.4.0 起把 `SpringDocConfigProperties.getGroupConfigs()` 返回值 List→Set，而 knife4j 4.5.0（最新发布版）的增强类 `Knife4jOpenApiCustomizer` 仍按 List 调用 → 崩溃；
  - 能同时满足这两点的 knife4j 4.6 修复版从未发布到 Maven 中央仓库（knife4j 已停更，2024-01 后无新版）。
- 最终修复：**弃用 knife4j，改用官方 springdoc + Swagger UI**。
  - `pom.xml`：删除 `knife4j-openapi3-jakarta-spring-boot-starter`，只保留 `springdoc-openapi-starter-webmvc-ui:2.8.13`；
  - `application.yaml`：删除 `knife4j:` 配置块；
  - `README.md`：文档入口 `doc.html` → `swagger-ui.html`，技术栈行 knife4j → SpringDoc。
  - 项目本无任何 knife4j/swagger 注解（无 `@ApiSupport/@Tag/@Operation`），故改动零风险。
- 顺带：`GlobalExceptionHandler` 新增 `NoResourceFoundException` 处理，返回 404 + warn 日志，不再打印 ERROR 堆栈（纯后端访问 /、/favicon.ico 属正常 404）。
- 验证：`mvn test` 14 个测试全绿（含 SkyTakeOutAiApplicationTests 上下文加载 ~11s，证明 springdoc 自动装配无冲突）；`dependency:tree` 确认已无 xiaoymin/knife4j。
- 备注：Windows 下 `mvn` 在 Git Bash 报 plexus classworlds 错误，须用 PowerShell 运行；PowerShell 重定向 `*>` 输出为 UTF-16，需 iconv 转码阅读。
